# Sprint 8 — позиционный рейтинг

## Цели

- фактический рейтинг нового пользователя равен 0 и показывается как `—`;
- до старта фиксируются рейтинг, посев и ожидаемое место;
- награда зависит от разницы ожидаемого и фактического места;
- изменение за контест ограничено `[-500, +500]`;
- рейтинг находится в диапазоне `[0, 3000]`;
- после первоначальной выдачи рейтинга базовая сумма delta равна примерно нулю, а контролируемый
  системный прирост составляет 1 пункт на активного участника;
- контест с одним активным участником не является рейтинговым.

## Стартовый снимок

При переводе контеста в `RUNNING` создаётся неизменяемый `ContestRatingSnapshot`. В нём сохраняются:

- длительность;
- сумма максимальных баллов задач;
- количество зарегистрированных участников;
- `ratingAtStart`, `seedPlace` и `expectedPlace` каждого участника.

Посев сортируется по рейтингу, затем по времени регистрации. До запуска предварительная таблица
динамическая, после запуска используются только сохранённые значения.

Ожидаемое место:

```text
expectedPlace = 1 + Σ P(opponent finishes ahead)
P(A beats B) = 1 / (1 + 10 ^ ((ratingB - ratingA) / 400))
```

Для финального расчёта ожидание строится по активным участникам, но по их зафиксированным стартовым
рейтингам. Неявившиеся не создают рейтинговую инфляцию.

## Фактическое место

По каждой задаче учитывается последняя посылка. Она сразу заменяет предыдущую, даже если ещё не
проверена:

```text
finalScore ?? preliminaryScore ?? 0
```

Сортировка:

1. сумма баллов по убыванию;
2. время последней посылки по возрастанию с полной точностью временной метки;
3. UUID как детерминированный последний критерий.

Места уникальны: при равных баллах более ранняя последняя посылка выигрывает тай-брейк.

## Формула `placement-v2`

Нормализованное отклонение от ожидания:

```text
performance = (expectedPlace - actualPlace) / (participants - 1)
```

Вес контеста — среднее трёх коэффициентов:

- длительность относительно 90 минут;
- максимальный балл относительно 500;
- размер активного состава.

Каждый коэффициент ограничен, общий вес находится примерно между 0.67 и 1.0. Небольшие и короткие
контесты влияют слабее, полноценные получают вес 1.

Основная delta:

```text
performanceDelta = round(500 × contestWeight × performance)
```

У рейтинговых игроков изменения почти нулевые по сумме. Система добавляет контролируемый прирост
`+1` на участника и перераспределяет заблокированные потолком/полом изменения, сначала уменьшая
потери или выигрыши к нулю.

## Новички

Участник со стартовым рейтингом 0 получает onboarding-выдачу:

```text
100 + 100 × actualScore
```

Она умножается на вес контеста. `actualScore` равен 1 у победителя и 0 у последнего. Минимальная
итоговая delta новичка — `+25`, максимальная — `+500`.

Эта выдача является осознанным созданием рейтинга для нового пользователя. После выхода игроков из
нулевой зоны система возвращается к почти консервативному обмену.

## Ограничения и безопасность

- меньше двух активных участников — расчёт не выполняется;
- регистрация закрывается при старте;
- повторный расчёт использует прежний рейтинг применения и не удваивает delta;
- старый тур нельзя впервые рассчитать после более нового;
- более ранний тур нельзя пересчитать после применения последующих изменений;
- итоговый рейтинг ограничен `[0, 3000]`;
- изменение ограничено `[-500, +500]`;
- `maxRating` восстанавливается из полной рейтинговой истории.

## Примеры для стандартного контеста

Четыре новых игрока с равным ожиданием и местами 1–4 получили при проверке:

```text
+422, +235, +48, +25
```

Четыре игрока с рейтингом 1500:

```text
+235, +79, -77, -233
```

Сумма равна `+4`: ровно по одному системному пункту на участника.

При полном перевороте посева `2000, 1500, 1000, 500`:

```text
-459, -155, +157, +461
```

Сумма также равна `+4`.
