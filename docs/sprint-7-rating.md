# Sprint 7 — рейтинг и история

> Формула `pairwise-v1`, описанная ниже, сохранена как история Sprint 7 и больше не используется.
> Актуальная система — `placement-v2`, см. [Sprint 8](./sprint-8-placement-rating.md).

## Результат

После завершения контеста система рассчитывает изменения рейтинга участников с посылками. До первого
такого расчёта `currentRating = 0`, а интерфейс показывает `—`. Значение 500 используется только как
внутренняя база первого расчёта.

Профиль показывает текущий рейтинг, максимум, звание, SVG-график роста и историю контестов с местом,
баллами и delta.

## Данные

- `RatingCalculation` — один версионированный запуск на контест, автор, количество участников и
  параметры формулы;
- `RatingChange` — предыдущий и новый рейтинг, delta, место, результат, ожидаемый и фактический
  попарный score.

История неизменяемо связана с контестом и пользователем. Повторный расчёт обновляет тот же расчёт и
не применяет delta второй раз.

## Формула `pairwise-v1`

1. Берётся последняя посылка участника по каждой задаче.
2. Используется `finalScore`, иначе `preliminaryScore`, иначе 0.
3. Участники сравниваются попарно: победа 1, ничья 0.5, поражение 0.
4. Ожидаемый результат пары:

   `E = 1 / (1 + 10 ^ ((ratingOpponent - rating) / 400))`

5. Изменение:

   `delta = round(80 × (actualAverage - expectedAverage))`

6. Delta ограничивается диапазоном `[-100, +100]`.

Для единственного участника с положительным результатом применяется небольшой стартовый бонус от 5
до 20. Рейтинг не может стать меньше 1.

## Защита пересчёта

- незавершённый контест рассчитать нельзя;
- пользователи без посылок не получают рейтинг;
- старый контест нельзя впервые посчитать после более нового;
- если после контеста уже применены более поздние изменения, пересчёт блокируется;
- максимальный рейтинг восстанавливается из всей сохранённой истории.

## API

| Метод  | Маршрут                           | Доступ            |
| ------ | --------------------------------- | ----------------- |
| `POST` | `/api/admin/contests/[id]/rating` | admin             |
| `GET`  | `/api/admin/contests/[id]/rating` | admin             |
| `GET`  | `/api/contests/[id]/rating`       | доступ к контесту |

При переводе контеста в `FINISHED` расчёт планируется автоматически через `after()`. В конструкторе
остаётся кнопка безопасного ручного пересчёта.

## Ручная проверка

1. Завершить контест минимум с двумя участниками и посылками.
2. Дождаться расчёта или нажать «Рассчитать рейтинг».
3. Проверить delta в API и профилях.
4. Повторить расчёт и убедиться, что рейтинг не изменился второй раз.
5. Открыть профиль и проверить график, максимум, звание и историю участия.
