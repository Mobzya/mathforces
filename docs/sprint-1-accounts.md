# Sprint 1 — аккаунты, организации и профиль

## Результат

Пользователь может зарегистрироваться с новой или существующей организацией, войти, выйти, открыть
публичный профиль и изменить ник, описание, класс и организацию.

## Таблицы

- `User` — идентификатор, нормализованные email/ник, password hash, профиль, технический рейтинг 0
  до первого участия, роль и текущая организация;
- `Organization` — уникальное нормализованное название и создатель;
- `UserOrganizationHistory` — неизменяемый журнал вступления и переходов;
- `AuthSession` — хеш непрозрачного session token и срок действия.

Один пользователь всегда связан ровно с одной организацией. Фото, контесты и рейтинг-история
намеренно не добавлены в этот спринт.

## API

| Метод   | Маршрут                   | Доступ              |
| ------- | ------------------------- | ------------------- |
| `POST`  | `/api/auth/register`      | публичный           |
| `POST`  | `/api/auth/login`         | публичный           |
| `POST`  | `/api/auth/logout`        | текущая сессия      |
| `GET`   | `/api/users/me`           | текущая сессия      |
| `PATCH` | `/api/users/me`           | текущая сессия      |
| `GET`   | `/api/users/[id]`         | публичный           |
| `GET`   | `/api/organizations`      | публичный           |
| `POST`  | `/api/organizations`      | текущая сессия      |
| `PATCH` | `/api/organizations/[id]` | создатель или админ |

## Безопасность

- пароль хешируется `scrypt` с уникальной солью;
- сырой session token хранится только в `HttpOnly`, `SameSite=Lax` cookie;
- в БД записывается только SHA-256 хеш session token;
- mutating API проверяют `Origin`;
- сервер повторно валидирует все поля;
- публичный пользователь не содержит email, password hash или роль;
- смена организации выполняется транзакционно и записывается в историю.

Rate limiting, восстановление пароля и подтверждение email не входят в Sprint 1 и должны быть
добавлены до открытого production-запуска.

## Ручная проверка

1. Запустить PostgreSQL и миграцию.
2. Открыть `/register` и создать аккаунт с новой организацией.
3. В профиле изменить описание и класс.
4. Создать новую организацию через настройки и перейти в неё.
5. Выйти и войти повторно.
6. Открыть профиль без авторизации и убедиться, что email не показывается.
