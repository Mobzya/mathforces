# Sprint 10 — релизная готовность

В исходном roadmap отдельный Sprint 10 не был описан. Этот этап закрывает оставшиеся критерии
приёмки PWA и финальный пункт плана: полировку, рефакторинг и воспроизводимую проверку перед
релизом.

## Установка и обновление PWA

- manifest содержит `id`, `scope`, PNG-иконки 192×192 и 512×512, отдельную maskable-иконку и Apple
  touch icon;
- Chromium-подобные браузеры получают нативную кнопку установки;
- на iPhone и iPad показывается короткая инструкция для Safari;
- отклонённое предложение не появляется снова в течение семи дней;
- новая версия service worker ожидает согласия пользователя, после чего активируется и один раз
  перезагружает страницу.

Service worker включается только в production. В development старые регистрации и кэш Mathforces
автоматически удаляются, чтобы они не скрывали изменения кода.

## Офлайн-стратегия

Service worker использует два версионированных кэша:

- `shell` — офлайн-страница, иконки и ранее посещённые публичные маршруты;
- `static` — хэшированные Next.js assets и PWA-ресурсы.

Навигация работает по стратегии network-first с таймаутом пять секунд. В navigation cache входят
только действительно публичные `/`, `/rating`, `/settings` и `/offline`, причём ключ сохраняет query
string. Зависящие от cookie `/contests`, `/login` и `/register`, API, фото решений, приватные
страницы и ответы React Server Components не кэшируются. При потере сети интерфейс показывает общий
статус и действие «Повторить», а неизвестный маршрут открывает безопасную офлайн-страницу.

Удаляются только кэши с префиксом Mathforces: service worker не затрагивает данные других приложений
на том же origin.

## Состояния и доступность

- глобальный skeleton для переходов;
- понятные страницы ошибки, 404 и отсутствия сети с повтором действия;
- skip-link к основному содержимому;
- единый заметный `focus-visible` для клавиатурной навигации;
- объявления статуса сети, установки и обновления через `aria-live`;
- интерактивные элементы сохраняют минимальную мобильную высоту 44 px.

## Публичная таблица рейтинга

Маршрут `/rating` содержит всех зарегистрированных пользователей, включая участников без рейтинговых
контестов. Они имеют фактический рейтинг `0`, но в интерфейсе продолжают отображаться как `—`.

- основной порядок: рейтинг по убыванию, затем нормализованный ник;
- фильтр организации не скрывает места общей таблицы, а строит отдельную классификацию среди её
  текущих участников;
- движение места сравнивается с положением непосредственно до последнего глобально рассчитанного
  рейтингового контеста;
- участник, не игравший последний тур, также может потерять или получить места из-за изменений
  других игроков;
- каждая строка и карточка пьедестала ведут в публичный профиль;
- выдача разбита на страницы по 50 участников и поддержана составными индексами PostgreSQL.

`/api/rating/stream` проверяет изменения каждые четыре секунды и отправляет данные только при
изменении рейтинга, порядка или состава страницы. Клиент анимирует перестановку строк, изменение
чисел и направление движения. Тот же FLIP-переход и анимированные числа применяются к live-таблице
баллов контеста.

## Защитные заголовки

На всех маршрутах выставляются:

- `X-Content-Type-Options: nosniff`;
- `X-Frame-Options: DENY`;
- `Referrer-Policy: strict-origin-when-cross-origin`;
- ограниченный `Permissions-Policy`;
- `Cross-Origin-Opener-Policy: same-origin`.

`sw.js` отдельно получает запрет долгого кэширования и `Service-Worker-Allowed: /`.

## Темы, настройки и профили

Шестерёнка в шапке открывает быстрое переключение системной, светлой и тёмной темы. Полная страница
`/settings` дополнительно управляет анимациями и плотностью таблиц. Предпочтения сохраняются в
`localStorage`, применяются скриптом до гидрации и поэтому не создают светлой вспышки при запуске
тёмной темы. Режим сокращённых анимаций также отключает Web Animations для live-строк и цифровых
счётчиков.

Профиль поддерживает:

- публичный аватар JPEG, PNG или WebP до 5 МБ;
- пять акцентных палитр и четыре рисунка обложки;
- любимую математическую тему;
- отдельную видимость класса и организации;
- описание, ник, класс и организацию из прежнего редактора.

Аватары проверяются по сигнатуре файла, хранятся через общий `ObjectStorage`, имеют версионированный
URL и удаляются при замене. Цвет ника не относится к кастомизации: он всегда вычисляется из текущего
рейтингового звания.

График рейтинга использует шкалу 0–3000 с горизонтальными цветными диапазонами званий. Каждая точка
соответствует контесту, соседние точки соединяются отрезками цвета нового звания, а дата, рейтинг и
изменение доступны прямо на графике.

## Проверка перед релизом

После production-сборки запустить web, worker и smoke-сценарий:

```bash
npm run build
npm run start
npm run worker:judge
npm run test:smoke
npm run test:unit
npm run test:queue
npm run test:avatar
npm run test:submission
```

Для удалённого стенда:

```bash
SMOKE_BASE_URL=https://mathforces.example npm run test:smoke
```

Smoke-сценарий проверяет главную, список контестов, офлайн-страницу, manifest, service worker,
защитные заголовки и `/api/health`. Для реального релиза также нужны HTTPS, внешний PostgreSQL,
постоянный object storage, отдельный worker-процесс и ежедневная команда `npm run backup:create`.
