# Sprint 4 — live-таблица результатов

## Результат

Страница `/contests/[id]/standings` показывает зарегистрированных участников, баллы по пяти задачам,
сумму и место. Таблица обновляется через Server-Sent Events без перезагрузки страницы.

На мобильном экране используются компактные карточки, на широком — таблица. Клик по участнику или
баллу открывает подробности по задачам, комментарии и историю изменений.

## Правило расчёта

Для каждой пары «участник + задача» учитывается последняя по времени посылка:

1. если есть `finalScore`, используется он;
2. иначе используется `preliminaryScore`;
3. если оценки ещё нет, в ячейке отображается `—`, а в сумму входит `0`.

Повторная отправка заменяет предыдущую, даже если её текущий балл ниже. Это соответствует правилу
последней перепроверяемой посылки.

Участники сортируются по убыванию суммы. При равной сумме выше находится тот, кто раньше сделал свою
последнюю отправку, затем применяется сортировка по нику. Одинаковая сумма получает одинаковое
отображаемое место.

## Архитектура

`ContestStandings`, `StandingRow` и `StandingCell` — типизированные read-models, вычисляемые из
`ContestRegistration`, `Problem` и `Submission`. Отдельные таблицы-копии не создаются, поэтому
standings не могут рассинхронизироваться с посылками.

Расчёт находится в `server/standings/queries.ts` и не зависит от UI или SSE.

## API

| Метод   | Маршрут                               | Назначение                                 |
| ------- | ------------------------------------- | ------------------------------------------ |
| `GET`   | `/api/contests/[id]/standings`        | текущий снимок таблицы                     |
| `GET`   | `/api/contests/[id]/standings/stream` | SSE-обновления каждые 4 секунды            |
| `PATCH` | `/api/standings/[submissionId]`       | финальный балл и комментарий, только admin |

SSE использует те же права доступа, что и страница контеста. Для закрытого контеста данные доступны
только нужной организации и администратору.

## Административная коррекция

В карточке результата администратор может изменить итоговый балл и добавить комментарий. Балл
проверяется относительно максимума задачи. Каждое изменение записывается в `SubmissionComment` с
предыдущим и новым значением, статусом и временем, после чего попадает в следующий SSE-снимок.
