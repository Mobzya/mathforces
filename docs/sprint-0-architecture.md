# Sprint 0 — фундамент Mathforces

## Цель

Поднять проверяемый каркас, на котором следующие спринты смогут добавлять доменные модули без
перестройки UI и инфраструктуры.

## Слои

- `app/` — страницы, layout, manifest и route handlers;
- `components/` — дизайн-примитивы и составные UI-блоки;
- `lib/` — общие утилиты без бизнес-логики;
- `server/` — серверные модули и data access;
- `prisma/` — схема и будущие миграции PostgreSQL;
- `services/` — будущие заменяемые интеграции storage/OCR/judge;
- `workers/` — будущие фоновые обработчики.

Зависимости направляются от UI к application/domain/data-access слоям. Интеграции не должны
проникать напрямую в компоненты.

## Маршруты

| Маршрут          | Назначение в Sprint 0               |
| ---------------- | ----------------------------------- |
| `/`              | публичная главная                   |
| `/login`         | UI входа, без отправки данных       |
| `/register`      | UI регистрации и выбора организации |
| `/contests`      | демонстрационный список контестов   |
| `/contests/[id]` | демонстрационный экран контеста     |
| `/profile/[id]`  | демонстрационный профиль            |
| `/admin`         | безопасная заглушка админ-панели    |
| `/offline`       | fallback для PWA                    |
| `/api/health`    | проверка web + PostgreSQL           |

## База

Используется Prisma 7 с `@prisma/adapter-pg`. Клиент создаётся один раз в `server/db/client.ts`,
чтобы hot reload не создавал лишние пулы соединений. URL подключения находится только в окружении.

В Sprint 0 доменные модели не добавляются: ТЗ требует сначала отдельно зафиксировать точные
контракты User и Organization. Это предотвращает необоснованную миграцию и лишние сущности.

## PWA

`app/manifest.ts` формирует web app manifest. Service worker кэширует только публичный app shell и
использует network-first стратегию для навигации. API и мутации не кэшируются. Регистрация service
worker выполняется только в production.

Перед production-релизом SVG-иконки следует дополнить PNG-вариантами 192×192 и 512×512 для
максимально широкой поддержки установщиков.

## Следующий спринт

Sprint 1 должен добавить:

1. согласованную Prisma-схему `User`, `Organization` и историю смены организации;
2. серверную валидацию и безопасное хранение паролей;
3. session-based auth;
4. API организаций и профиля;
5. замену демонстрационных данных профиля на данные PostgreSQL.

## Известные риски

- На 19 июля 2026 `npm audit` отмечает 5 moderate-уязвимостей во вложенных зависимостях актуальных
  Next.js 16.2.10 и Prisma 7.8.0. High и critical уязвимостей нет. Предложенный npm автофикс
  откатывает major-версии и потому не применяется; зависимости нужно обновить после официальных
  patch-релизов.
- Dev и production build используют webpack. Turbopack в текущем управляемом контейнере не может
  стабильно запустить внутренний CSS-процесс; это ограничение среды проверок, а не причина менять
  архитектуру приложения.
- `next start` в этом же контейнере не отдавал prerendered-страницы, хотя dynamic-маршруты отвечали
  и статические HTML-файлы были сформированы корректно. Все маршруты проверены через
  `next dev --webpack`; production runtime нужно повторно проверить вне sandbox перед первым
  деплоем.
