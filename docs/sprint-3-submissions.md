# Sprint 3 — фото-посылки

## Результат

Участник активного контеста может выбрать задачу, сделать фотографию решения на телефоне или
загрузить изображение и отправить посылку. После загрузки посылка получает статус `QUEUED` и
появляется в публичной ленте.

## Таблицы

- `Submission` — автор, контест, задача, статус, предварительный и финальный баллы, комментарии и
  публичность;
- `SubmissionFile` — storage key, исходное имя, MIME-тип, размер и SHA-256;
- `SubmissionComment` — системные, AI- и административные записи по посылке.

Фотография не хранится в PostgreSQL и не попадает в публичный JSON.

## Хранилище

`services/storage/` задаёт заменяемый контракт object storage. Локальная реализация сохраняет файлы
вне `public` в `SUBMISSION_STORAGE_DIR` (по умолчанию `storage/submissions`). Для production её
можно заменить S3-совместимым адаптером без изменения submission API.

Разрешены JPEG, PNG и WebP размером до 15 МБ. Формат проверяется по сигнатуре файла, а не только по
расширению или заголовку браузера.

Изображение выдаётся через `GET /api/submissions/[id]/image` только автору или администратору. Ответ
помечен `private, no-store`.

## API

| Метод   | Маршрут                          | Назначение                         |
| ------- | -------------------------------- | ---------------------------------- |
| `POST`  | `/api/submissions`               | отправить изображение решения      |
| `GET`   | `/api/contests/[id]/submissions` | публичная лента без фотографий     |
| `GET`   | `/api/submissions/[id]`          | данные одной посылки               |
| `GET`   | `/api/submissions/[id]/image`    | защищённое изображение             |
| `PATCH` | `/api/submissions/[id]`          | изменить статус/балл, только admin |

Клиент передаёт изображение как бинарное тело запроса. Метаданные контеста и задачи находятся в
query string, исходное имя — в служебном заголовке.

## Права и ограничения

- отправлять решения может зарегистрированный участник активного контеста;
- задача обязана принадлежать указанному контесту;
- для закрытого контеста сохраняются ограничения организации;
- публичная лента содержит только время, ник, задачу, статус и баллы;
- автор видит ссылку на свою фотографию, другие участники — нет;
- административный балл не может превышать максимум задачи.

## Обновление статусов

Лента опрашивает API каждые восемь секунд. Запись со статусом `QUEUED` является устойчивой очередью
MVP: будущий judge worker сможет выбирать такие записи и переводить их в `PROCESSING`,
`PRELIMINARY_READY` или `NEEDS_REVIEW`.

Полноценный OCR и автоматический скоринг относятся к Sprint 6. В Sprint 3 реализованы приём,
приватное хранение, очередь, показ статуса и контракт для предварительного балла.
