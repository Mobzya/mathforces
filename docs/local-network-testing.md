# Локальное тестирование с нескольких устройств

Эта инструкция позволяет открыть Mathforces на телефонах и других компьютерах. Основной компьютер
может быть подключён по Ethernet: если телефон подключён по Wi-Fi к тому же роутеру, оба устройства
обычно уже находятся в одной локальной сети. Wi-Fi-адаптер на основном компьютере не требуется.

## 1. Запуск

На основном компьютере:

```bash
docker compose up -d postgres
npm run dev:lan
```

После успешных миграций терминал покажет один или несколько адресов:

```text
На этом компьютере: http://localhost:3000
На телефоне или другом ПК: http://192.168.1.25:3000
```

Оставьте терминал открытым. Для остановки нажмите `Ctrl+C`: web и worker завершатся вместе.

## 2. Подключение устройств

1. Подключите устройства к тому же роутеру: компьютер может использовать Ethernet, а телефон Wi-Fi.
2. Отключите мобильный VPN, если он запрещает доступ к локальной сети.
3. Откройте напечатанный LAN-адрес в браузере устройства.
4. Для проверки базы откройте `/api/health`; ожидаемый ответ имеет `status: "ok"`.
5. Создайте отдельные аккаунты в разных браузерах и проверьте регистрацию, контест, посылки и
   live-таблицу.

Используйте LAN-адрес и на основном компьютере, если хотите видеть ту же cookie-сессию. Для браузера
`localhost:3000` и `192.168.x.x:3000` — разные сайты с разными cookie.

## 3. Если IP не определился

Linux:

```bash
ip -4 addr
```

Windows PowerShell:

```powershell
ipconfig
```

macOS:

```bash
ipconfig getifaddr en0
```

Нужен частный IPv4, обычно начинающийся с `192.168.`, `10.` или `172.16`–`172.31`.

## 4. Firewall

Если страница открывается на компьютере, но недоступна на телефоне, разрешите входящие TCP-
соединения на порт 3000 только для локальной сети.

Пример для Ubuntu с UFW:

```bash
sudo ufw allow from 192.168.0.0/16 to any port 3000 proto tcp
```

Подставьте реальную подсеть. Не открывайте порт для всего интернета. После теста правило можно
удалить через `sudo ufw status numbered` и `sudo ufw delete <номер>`.

В Windows разрешите Node.js для Private networks в диалоге Windows Defender Firewall. Не включайте
разрешение для Public networks.

## 5. Безопасность

- PostgreSQL из `docker-compose.yml` привязан к `127.0.0.1:5432` и не должен быть виден другим
  устройствам.
- Не настраивайте port forwarding на роутере.
- Не используйте LAN-режим в кафе, гостинице или другой публичной сети.
- Не отправляйте в тест настоящие персональные данные и реальные олимпиадные работы.
- После теста остановите приложение через `Ctrl+C`.

## 6. Ограничения HTTP

Обычная работа сайта, аккаунты, контесты и загрузка выбранных фотографий доступны по HTTP в LAN.
Однако браузеры считают такой адрес небезопасным контекстом:

- service worker и установка PWA обычно недоступны;
- некоторые camera API могут быть заблокированы, хотя обычный выбор или съёмка файла через системный
  file picker на телефоне часто работает;
- для теста полноценной PWA нужен локальный HTTPS-сертификат либо временный защищённый tunnel.

## 7. Тестирование через интернет

Если устройства подключены к разным роутерам, включена изоляция Wi-Fi-клиентов или нужно проверить
сайт через мобильный интернет, используйте временный Cloudflare Quick Tunnel.

В первом терминале запустите приложение:

```bash
docker compose up -d postgres
npm run dev
```

Когда приложение откроется на `localhost:3000`, во втором терминале выполните:

```bash
npm run tunnel
```

Docker при первом запуске загрузит официальный образ `cloudflare/cloudflared`. Через несколько
секунд в терминале появится адрес вида `https://random-name.trycloudflare.com`. Его можно открыть с
любого устройства, включая телефон на мобильном интернете. Благодаря HTTPS доступны secure-cookie и
браузерные функции, которым недостаточно обычного LAN HTTP.

Quick Tunnel не требует аккаунта, но его случайный URL фактически является ключом доступа:

- используйте только тестовые аккаунты и данные;
- не публикуйте URL в открытом доступе;
- не открывайте таким способом админку посторонним людям;
- после проверки нажмите `Ctrl+C` во втором терминале — адрес сразу перестанет работать;
- PostgreSQL при этом остаётся привязан к `127.0.0.1` и в туннель не попадает.

Для постоянной публичной эксплуатации Quick Tunnel не подходит: понадобится обычный хостинг,
управляемая PostgreSQL, резервные копии, домен и контроль доступа.

## 8. Диагностика

| Симптом                         | Что проверить                                                   |
| ------------------------------- | --------------------------------------------------------------- |
| `ERR_CONNECTION_REFUSED`        | терминал с `dev:lan`, IP и порт 3000                            |
| Долгое ожидание до старта       | `docker compose ps` и `npm run db:status`                       |
| Вход работает только на ПК      | открывается ли на ПК именно LAN-адрес, разрешены ли cookie      |
| Кнопки записи не обновляются    | нет ли старого service worker; в dev он удаляется автоматически |
| Посылка остаётся в очереди      | запущен ли worker в том же терминале                            |
| Устройства не видят друг друга  | client isolation/AP isolation в настройках Wi-Fi                |
| Tunnel пишет connection refused | сначала запущен ли сайт на `http://localhost:3000`              |
