# Sprint 6 — автоматическая предварительная проверка

## Результат

После загрузки фотография проходит пять независимых этапов:

1. подготовка изображения;
2. OCR;
3. извлечение структуры решения;
4. консервативный предварительный скоринг;
5. контроль confidence и маршрутизация на ручную проверку.

Pipeline запускается через `after()` после ответа загрузки и дублируется отдельным worker-процессом
для устойчивой очереди.

## Данные

- `Evaluation` — снимок rubric, распознанный текст, score, confidence, комментарий, режим и итог
  pipeline;
- `JudgeModelRun` — провайдер, этап, latency, confidence, безопасная сводка результата и ошибка
  каждого запуска.

Фотография и её байты в этих таблицах не сохраняются. Полный OCR-текст доступен через API только
автору решения и администратору.

## Оценивание MVP

Локальный Tesseract распознаёт печатный и разборчивый рукописный текст настолько, насколько
позволяет установленный language pack. Heuristic judge учитывает объём распознанного решения, связки
доказательства, формулы и итоговый вывод.

Оценка намеренно ограничена и сопровождается предупреждением, что математическая корректность не
подтверждена. Низкая уверенность, короткий текст, ошибка OCR и геометрическая терминология переводят
посылку в `NEEDS_REVIEW`.

Это безопасная заглушка перед подключением математической vision/LLM-модели: она демонстрирует
полный контракт и частичные баллы, но не изображает из себя экспертную проверку.

## API

| Метод  | Маршрут                            | Доступ                           |
| ------ | ---------------------------------- | -------------------------------- |
| `POST` | `/api/submissions/[id]/judge`      | автор или admin, только `QUEUED` |
| `POST` | `/api/submissions/[id]/rejudge`    | admin                            |
| `GET`  | `/api/submissions/[id]/evaluation` | автор или admin                  |

Админская перепроверка сохраняет прошлые `Evaluation`, поэтому история запусков не теряется. Ручной
итоговый балл по-прежнему имеет приоритет в standings.

## Проверка

1. Запустить `npm run dev` и при необходимости `npm run worker:judge`.
2. Отправить PNG/JPEG/WebP с читаемым решением.
3. Убедиться, что статус меняется `QUEUED → PROCESSING → PRELIMINARY_READY` или `NEEDS_REVIEW`.
4. Проверить предварительный балл, комментарий и confidence.
5. Открыть evaluation API автором решения.
6. Запустить перепроверку в админке и убедиться, что появилась новая Evaluation.
