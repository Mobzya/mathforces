# Участие в разработке Mathforces

Спасибо за интерес к проекту. Mathforces пока является рабочим MVP, поэтому изменения должны быть
небольшими, проверяемыми и сохранять совместимость данных.

## Подготовка окружения

```bash
cp .env.example .env
npm ci
docker compose up -d postgres
npm run db:deploy
npm run dev
```

## Перед изменениями

- Не добавляйте в Git `.env`, дампы, реальные фотографии решений и содержимое `storage`.
- Не редактируйте уже применённые миграции; создавайте новую миграцию.
- Для изменений оценивания обязательно описывайте влияние на предварительные и финальные баллы.
- Для изменений авторизации проверяйте LAN HTTP и production HTTPS cookie-политику отдельно.

## Кодстайл

- TypeScript используется в strict-режиме.
- Форматирование выполняет Prettier, семантические ошибки проверяет ESLint.
- Серверная бизнес-логика находится в `server`, UI — в `components`, маршруты — в `app`.
- В API возвращайте понятные русские ошибки и не раскрывайте внутренние исключения клиенту.
- Все административные изменения должны попадать в `AdminAction`.

```bash
npm run format
npm run check
```

## Изменения базы

После изменения `prisma/schema.prisma`:

```bash
npm run db:migrate
npm run db:generate
```

Проверьте созданный SQL до применения. В CI и production используются только готовые миграции через
`npm run db:deploy`.

## Проверки перед Pull Request

Минимальный набор:

```bash
npm run check
npm run security:audit
npm run build
```

Для изменений очереди, рейтинга или файлов дополнительно запустите соответствующий интеграционный
тест из `package.json`. PostgreSQL-тесты создают изолированные записи и очищают их в `finally`.

## Pull Request

Опишите:

1. пользовательский результат;
2. изменения схемы или API;
3. риски и обратную совместимость;
4. выполненные проверки;
5. скриншоты для заметных UI-изменений.
